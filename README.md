# لوحة إدارة سكينة — Sakina Admin Dashboard

تطبيق ويب **React + TypeScript** للوحة الإدارة بمنصة سكينة للصحة النفسية، مبني على:

- **فصل صارم للصلاحيات (RBAC)** حسب مصفوفة الأدوار الست في وثيقة المنتج.
- **الهوية البصرية لسكينة** المستخرجة من تطبيق المريض وداشبورد المعالج (تيل `#1D919E`، خط Tajawal، RTL).
- **بيانات تجريبية (Mock)** حالياً — التكامل مع الباك اند لاحقاً.

## التشغيل

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # بناء الإنتاج
npm run lint     # فحص الكود
```

## الأدوار والصلاحيات

من صفحة الدخول اختر الدور للدخول التجريبي (يوجّه تلقائياً لأول شاشة مسموحة):

| الدور | يشوف | ممنوع عنه |
|---|---|---|
| المدير الرئيسي | كل شيء + سجل التدقيق + الإعدادات | — |
| المدير | تشغيل + مالية، سجل قراءة | المحتوى السريري |
| المشرف الإكلينيكي | سريري كامل + تنبيهات | المال + هوية المرضى |
| الشريك المالي | حوالاته + تقارير أرباحه | الباقي كله |
| موظف الدعم | تذاكر الدعم + تنبيه Red Flag | العلاج + المال + المرضى |
| مدير المحتوى | الأسئلة الشائعة فقط | الباقي كله |

المصفوفة في `src/auth/permissions.ts` — كل شاشة لها مستوى وصول (`full | read | limited | denied`)
وقناع بيانات اختياري (بدون سريري، بدون هوية، حالة فقط، خاصة به، غير علاجي...).
الحارس `Guard` يعرض صفحة **غير مصرح** لأي شاشة `denied`.

## البنية

```
src/
  api/client.ts       عميل HTTP: Bearer token + Idempotency-Key + ApiError + مغلف Page<T>
  api/types.ts        عقود الباك اند (snake_case) من مرجعية API
  api/auth.ts         /api/v1/auth — login/refresh/logout/me
  api/admin.ts        /api/v1/admin/* — كل endpoints الإدارة
  services/data.ts    طبقة الخدمات: واجهة واحدة للشاشات تتبدل mock/API تلقائياً
  hooks/useAsync.ts   hook لتحميل البيانات من الخدمات
  auth/permissions.ts مصفوفة الصلاحيات + التسميات + القائمة الجانبية

  components/         Shell, Guard, ui primitives, Icon (SVG)
  data/mock.ts        بيانات تجريبية (المصدر البديل)
  screens/            16 شاشة
  theme.css           توكنات الهوية (Tajawal + ألوان سكينة)
```

## الربط بالباك اند

انسخ `.env.example` إلى `.env` واضبط:

```bash
VITE_API_URL=http://localhost:8000   # عنوان الـAPI (بدون / في النهاية)
VITE_API_MOCK=false                  # false = الاتصال الحقيقي، true = mock
```

- عند `VITE_API_MOCK=false` تعمل الشاشات على الـAPI فوراً بنفس الواجهة —
  الخدمات في `services/data.ts` تحوّل ردود الـAPI (uuid، snake_case، مغلف `{data, pagination}`)
  إلى نماذج العرض نفسها المستخدمة حالياً.
- تسجيل الدخول يصبح حقيقياً: `POST /api/v1/auth/login` برقم الواتساب وكلمة المرور،
  التوكن يُخزن في `localStorage` ويُرفق Bearer في كل طلب، وأي `401` يُخرج الجلسة تلقائياً.
- عمليات التعديل (مراجعة حوالة/مستند، اعتماد معالج، حالة تذكرة/راية) تُرسل
  `Idempotency-Key` تلقائياً كما يتطلب العقد.
- **مصفوفة الواجهة مطابقة لأدوار الـAPI المعلنة لكل endpoint** (أدق من الـPDF):
  - ممنوع على المشرف: المعالجون وطلبات الملفات (API يعطي 403).
  - ممنوع على الدعم: المرضى، المعالجون، الملفات، المدفوعات، السريري — الدعم له التذاكر فقط.
  - مدير المحتوى: `/admin/faqs` فقط (البرامج ممنوعة عليه في الـAPI).
  - الشريك المالي: `payments` + `withdrawals` + إلغاء الاشتراكات.
  - `/admin/overview` متاح للمدير والرئيسي فقط — بقية الأدوار تعتمد على endpointsها الخاصة.
- غير جاهز بعد للربط (يلزم توسّع لاحقاً): `programs` تُقرأ من mock (رد الـAPI يحتاج حقول الوحدات)،
  تفاصيل ملف المريض، التقارير، الإعدادات، والسحوبات لها endpoints جاهزة بلا شاشة مخصصة بعد.
- CORS: يجب أن يسمح الباك اند بمصدر الواجهة (`http://localhost:5173` أثناء التطوير).
