# لوحة إدارة سكينة — Sakina Admin Dashboard

تطبيق ويب **React + TypeScript** للوحة الإدارة بمنصة سكينة للصحة النفسية، مبني على:

- **فصل صارم للصلاحيات (RBAC)** حسب مصفوفة الأدوار الست في وثيقة المنتج.
- **الهوية البصرية لسكينة** المستخرجة من تطبيق المريض وداشبورد المعالج (تيل `#1D919E`، خط Tajawal، RTL).
- **بيانات تجريبية (Mock)** حالياً — التكامل مع الباك اند لاحقاً.

## التشغيل

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # بناء الإنتاج
npm run lint     # فحص الكود
```

## الأدوار والصلاحيات

من صفحة الدخول اختر الدور للدخول التجريبي (يوجّه تلقائياً لأول شاشة مسموحة):

| الدور | يشوف | ممنوع عنه |
|---|---|---|
| المدير الرئيسي | كل شيء + سجل التدقيق + الإعدادات | — |
| المدير | تشغيل + مالية، سجل قراءة | المحتوى السريري |
| المشرف الإكلينيكي | سريري كامل + تنبيهات | المال + هوية المرضى |
| الشريك المالي | حوالاته + تقارير أرباحه | الباقي كله |
| موظف الدعم | حالة الحسابات + تذاكر + رفع الطلبات | العلاج + المال |
| مدير المحتوى | المحتوى غير العلاجي فقط | الباقي كله |

المصفوفة في `src/auth/permissions.ts` — كل شاشة لها مستوى وصول (`full | read | limited | denied`)
وقناع بيانات اختياري (بدون سريري، بدون هوية، حالة فقط، خاصة به، غير علاجي...).
الحارس `Guard` يعرض صفحة **غير مصرح** لأي شاشة `denied`.

## البنية

```
src/
  auth/permissions.ts   مصفوفة الصلاحيات + التسميات + القائمة الجانبية
  auth/AuthContext.tsx  الدور الحالي (sessionStorage)
  components/           Shell, Guard, ui primitives, Icon (SVG)
  data/mock.ts          بيانات تجريبية
  screens/              14 شاشة
  theme.css             توكنات الهوية (Tajawal + ألوان سكينة)
```

## ملاحظات للتكامل لاحقاً

- استبدل `AuthContext` بمصادقة الباك اند الحقيقية واربط `role` بدور المستخدم.
- استبدل `data/mock.ts` بطبقة API (نفس الأنواع في `types.ts`).
- قرارات الحوالات/الطلبات حالياً تغيّر الحالة محلياً فقط — اربطها بـAPI مع تسجيل Audit.
